Automating My Desktop With Bash Scripting
Nov 15, 2024

Introduction
Whilst studying UNIX in a systems architecture lecture, I found myself thinking for the first time about
low-level coding, how it works what the challenges are and how I can start developing with less abstractions.

This led me to Bash scripting, a lower level programming language that interfaces directly with the OS
provided it is a UNIX based system which for me on MacOS was a perfect place to start!
A Bit About Bash

Bash stands for "Bourne-again SHell" and is the most common Shell used for UNIX based systems. Bash
is a great way to get into lower level programming and it is essentially a list of command lines for
the computer to execute using the Terminal.

Bash allows you to automate processes which can be very helpful, including pushing new changes to github
or in my case organising my desktop and sorting out my files automatically.
The Terminal

For me coming from design, the Terminal was my worst enemy! However as a developer I had no excuses,
so I began to use it regularly when accessing directories, creating files and running command lines to
check CPU usage, Battery health and much more.

I discovered that the simplicity of using command lines gave me that low level feeling that I was after
and helped me to understand how the computer works without simply relying on the interface and having
yet another layer of abstraction.

Feeling confident I decided to write some Bash scripts!

Learning Bash
I began by printing "Hello World" as it seems to be a developer ritual at this point! Simply calling
the echo command followed by the text printed this to the Terminal.

#!/bin/bash

echo "Hello World"

    For learning points, the #!/bin/bash is the boilerplate code needed to execute a Bash script it is
    called a Shebang which is basically combination of bash# and bang ! followed by the bash shell path.

After running a few test projects and experimenting with variables and file manipulation I decided to
start planning my filing system.

Sorting
So now I had a system in place, I needed a way to sort files into folders and the best way to do this
was to use a prefix.

---------------------------
File    File extension
---------------------------
OOP     OOP_filename.PDF
ADVOOP  ADVOOP_filename.PDF
SYARC   SYARC_filename.PDF
HCI     HCI_filename.PDF
PERS    PERS_filename.PDF
WORG    WORG_filename.PDF
---------------------------
These are the sample codes I came up with for each module.

The prefix system meant that each file needed to follow the logic of MODULE_filename.jpg and the script
will add it to the Module folder based on the prefix.

Sounds simple right? Let´s build it!

Creating the Folders
The first step was to define the logic to create the folders on my desktop, I used the mkdir command
and setup a variable DESKTOP_DIR for the desktop using the $ to define it.

#!/bin/bash

# define Desktop directory
DESKTOP_DIR="$HOME/Desktop"

# create folders for each category
mkdir -p "$DESKTOP_DIR/Documents/University/OOP" "$DESKTOP_DIR/Documents/University/HCI" \
         "$DESKTOP_DIR/Documents/University/SYARC" "$DESKTOP_DIR/Documents/University/ADVOOP" \
         "$DESKTOP_DIR/Documents/Personal" "$DESKTOP_DIR/Images" "$DESKTOP_DIR/Videos" \
         "$DESKTOP_DIR/Work" "$DESKTOP_DIR/Other"

echo "Folders created or verified!"

I added the file directory paths to the script all originating from the DESKTOP_DIR variable and ran
the program to test.

Sure enough, there were five new files created on my desktop! Unfortunately when I updated the logic
later to handle folders I ran into an irritating bug where all folders would be added to 'Other' but
by adding the folder names to a new array under a variable EXCLUDE_FOLDERS which then a new function
named is_excluded() will iterate through the array and check if these folders exist then return them,
thus stopping them from being moved.

The way this logic works is by returning 1 or 0 if the item is found or not, which is 0 for no errors
and 1 if there the condition is not met. We can use this logic in Bash to act as a boolean statement.

# exclude folders from sorting
EXCLUDE_FOLDERS=("Documents" "Images" "Videos" "Work" "Other")

# function to check if an item is in the EXCLUDE_FOLDERS array
is_excluded() {
	local item="$1"
	for folder in "${EXCLUDE_FOLDERS[@]}"; do
		if [[ "$item" == "$folder" ]]; then
			return 0  # item is in the exclude list
		fi
	done
	return 1  # item is not in the exclude list
}

    The learning points here are that we have used an array to list out all folder names and run a simple
    check using a temporary variable $1 declared using the local keyword which is the same as a locally
    defined variable within a method in Java. We have also used a for loop and run a check to see if
    folders match the new array and if so return 0 for true or 1 for false.

Sorting Logic
The next step was the sorting logic, this was a little more challenging, the key is to make sure that
each file ends up in the correct directory based on the prefix else the file ends up stored based on
it´s extension or in the 'Other' file.

I started by just using this logic for files, by defining a new function called organise_files() I ran
a for loop looking through items within my $DESKTOP_DIR variable and creating a local basename variable
called $item.

organise_files() {
	for item in "$DESKTOP_DIR"/*; do
		local basename=$(basename "$item")
}

Next step was to check for pre-existing folders, which another if statement that calls the previous
function is_excluded() and checks for file/folder names that match, then calls continue which moves the
loop onto the next item.

# skip excluded folders
if is_excluded "$basename"; then
	echo "Skipping $basename"
	continue
fi

    A learning point here is the fi command which is used for ending loops.

I then implemented logic for processing files by checking the prefix of each file name.

To do this I used an if then statement that creates a new variable $filename assigned to the basename
of each file, then another if statement that checks each filename prefix against my folder naming convention.

If the item matches, there is a defined directory path that leads to the new destination for the file.

After testing, the files now move to the correct directory, fantastic!

# process files
if [[ -f "$item" ]]; then
	filename=$(basename "$item")
	echo "Processing file: $filename"

	# check prefixes for files and move accordingly
	if [[ "$filename" == OOP* ]]; then
		mv "$item" "$DESKTOP_DIR/Documents/University/OOP/"
	elif [[ "$filename" == HCI* ]]; then
		mv "$item" "$DESKTOP_DIR/Documents/University/HCI/"
	elif [[ "$filename" == SYARC* ]]; then
		mv "$item" "$DESKTOP_DIR/Documents/University/SYARC/"
	elif [[ "$filename" == ADVOOP* ]]; then
		mv "$item" "$DESKTOP_DIR/Documents/University/ADVOOP/"
	elif [[ "$filename" == WORK* ]]; then
		mv "$item" "$DESKTOP_DIR/Work/"

    A good learning point is the mapping of directories which follows the standard format of filing
    systems. Another point is how I defined the prefix by using PREFIX* to check if a file name begins
    with specific characters.

The final step for the for loop was to utilise the same logic but this time for file extensions such as
.pdf or .jpg.

This was similar to the last loop, except that that this time the * is placed before the extension
telling the OS to only look at the end of the file name.

# sort by file type if no matching prefix
elif [[ "$filename" == *.pdf || "$filename" == *.docx || "$filename" == *.txt ]]; then
	mv "$item" "$DESKTOP_DIR/Documents/Personal/"
elif [[ "$filename" == *.jpg || "$filename" == *.jpeg || "$filename" == *.png || "$filename" == *.gif ]]; then
	mv "$item" "$DESKTOP_DIR/Images/"
elif [[ "$filename" == *.mp4 || "$filename" == *.mov || "$filename" == *.avi ]]; then
	mv "$item" "$DESKTOP_DIR/Videos/"
else
	mv "$item" "$DESKTOP_DIR/Other/"
fi

Updating for Folders
With the logic now in place for sorting files, I quickly realised that was only half the problem, now
to deal with folders.

Thankfully the logic was almost identical so it was another case of checking the prefix and sorting the
folder appropriately to the correct directory.

# process directories that are not in the exclusion list
elif [[ -d "$item" ]]; then
	dirname=$(basename "$item")
	echo "Processing directory: $dirname"  # Debug statement

	# check prefixes for directories and move accordingly
	if [[ "$dirname" == OOP* ]]; then
		mv "$item" "$DESKTOP_DIR/Documents/University/OOP/"
	elif [[ "$dirname" == HCI* ]]; then
		mv "$item" "$DESKTOP_DIR/Documents/University/HCI/"
	elif [[ "$dirname" == SYARC* ]]; then
		mv "$item" "$DESKTOP_DIR/Documents/University/SYARC/"
	elif [[ "$dirname" == ADVOOP* ]]; then
		mv "$item" "$DESKTOP_DIR/Documents/University/ADVOOP/"
	elif [[ "$dirname" == WORK* ]]; then
		mv "$item" "$DESKTOP_DIR/Work/"
	else
		# if the directory doesn´t match a prefix, move it to "Other"
		mv "$item" "$DESKTOP_DIR/Other/"
	fi
fi

Testing the Project
Now with the completed script I could run some tests.

I started with a test case of adding a few files and folders with the OOP prefix and running the script
from the terminal using the chmod u+x command to modify the script to be executable.

Then executing the script with ./file_system.sh and sure enough all items were sorted into the OOP directory.

Feeling good, I then ran a couple more test cases with differing prefixes and each time the script ran,
all files were sorted correctly.

Excellent! But this script isn´t useful if I have to manually run it, so I found out how to automate it by
using a while loop and the sleep command to run the script every 60 seconds, solving the automation problem.

# run the function in an infinite loop with a delay
while true; do
	organise_files
	sleep 60 # check every 60 seconds
done

organise_files() {
