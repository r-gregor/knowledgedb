Renaming all files in a folder using the folder name
20 July 2026

   I find myself doing this every month so I find myself Googling this every month so, in the spirit of
   "write about it so you never forget it", I decided to write it down. And, who knows, it might be
   useful for you too.

   When I get my photography scans back from the lab they arrive named with a sequential number
   that is neat but useless.

ThomasRigb036944
+-- 000001.JPG
+-- 000007.JPG
+-- 000008.JPG
...
+-- 000030.JPG

   The associated Field Notes all have a standard naming convention of "Camera Name plus ISO Date":
   Minolta SRT303 2026-07-09.

   When I share my images on my website, the original file is copied into the repo which results in even
   less helpful files names like 000001 (4).JPG.

   So, I have added this function into my .bash_functions file (remembering, naturally, to source
   ~/.bashrc!)

mvff() {
	for f in *; do
		[ -f "$f" ] && mv -- "$f" "$(basename "$PWD")-$f"
	done
}

   [ -f "$f" ] checks that we´re actually looking at a file, not a directory. If it´s not a file, the &&
   short-circuits and we skip it - no accidental folder renaming.

   $(basename "$PWD") grabs just the name of the current folder (not the full path), which is what gets
   used as the prefix.

   mv -- "$f" "..." does the actual rename, tacking the folder name onto the front of the original
   filename. The -- is a little bit of insurance - it tells mv "everything after this is a filename, not
   a flag," which saves you if you ever end up with a scan named something silly like -000001.JPG.

   Now, when I´ve extracted my scans, I quickly rename the folder mv ThomasRigby036944 "Minolta SRT303
   2026-07-09", cd into it and run mvff to get meaningful filenames in a fraction of a second.
Minolta SRT303 2026-07-09/
+-- Minolta SRT303 2026-07-09-000001.JPG
+-- Minolta SRT303 2026-07-09-000007.JPG
+-- Minolta SRT303 2026-07-09-000008.JPG
+-- Minolta SRT303 2026-07-09-000009.JPG
...
+-- Minolta SRT303 2026-07-09-000030.JPG

   A note for future-me: run it twice (on purpose or, likely, by accident) and you´ll get double
   prefixes, since it doesn´t check whether the name´s already there. I could add a check in but that´s
   overkill for this use, I think; the function is supposed to be quick and dumb but effective.

   Another side note: This is also possible using the "bulk rename" capability in MacOS Finder and Nemo
   (which I use on Linux Mint). But the terminal is, in many ways, quicker and more intuitive.
