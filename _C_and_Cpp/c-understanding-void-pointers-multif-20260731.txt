void Pointer in C
4 Jul, 2026

   A void pointer in C is a special type of pointer that can store the address of any data type. Since
   it does not have an associated data type, it is often referred to as a generic pointer.
     * A void pointer can hold the address of variables of any data type.
     * Before accessing the value stored at a void pointer, it must be explicitly typecast to the
       appropriate pointer type.

   Example: The following program demonstrates that a void pointer can store the address of different
   data types

#include <stdio.h>

int main() {
	int a = 10;
	char b = 'x';

	// Void pointer stores address of int
	void* ptr = &a;

	// Void pointer stores address of char
	ptr = &b;

	return 0;
}

Properties of Void Pointers

Void Pointers Cannot Be Dereferenced Directly
   Since a void pointer has no associated data type, the compiler does not know how many bytes should be
   accessed during dereferencing.

   Example: Invalid Dereferencing
#include <stdio.h>

int main() {
	int a = 10;
	void* ptr = &a;
	printf("%d", *ptr);

	return 0;
}

   Output
Compiler Error: 'void*' is not a pointer-to-object type

   To access the value stored at a void pointer, it must first be typecast to the correct pointer type.

   Example: Dereferencing After Typecasting
#include <stdio.h>

int main() {
	int a = 10;
	void* ptr = &a;
	// The void pointer 'ptr' is cast to an integer pointer
	// using '(int*)ptr' Then, the value is dereferenced
	// with `*(int*)ptr` to get the value at that memory
	// location
	printf("%d", *(int*)ptr);
	return 0;
}

10

   Explanation: The void pointer is first converted to an integer pointer using (int*)ptr, after which
   it can be safely dereferenced.

Pointer Arithmetic Is Not Allowed on Void Pointers
   According to the [12]C standard, pointer arithmetic cannot be performed directly on void pointers
   because the size of the pointed object is unknown. However, some compilers such as GCC allow pointer
   arithmetic on void pointers by treating the size of void as 1 byte.
#include <stdio.h>

	// Declare and initialize an integer array 'a' with two
	// elements
	int a[2] = { 1, 2 };
	// Declare a void pointer and assign the address of
	// array 'a' to it
	void* ptr = &a;

	// Increment the pointer by the size of an integer
	ptr = ptr + sizeof(int);

	// The void pointer 'ptr' is cast to an integer
	// pointer using '(int*)ptr' Then, the value is
	// dereferenced with `*(int*)ptr` to get the value at

     convert the void pointer to a character pointer before performing pointer arithmetic.

Applications of Void Pointers in C
   Void pointers are widely used in C programming because they provide generic programming capabilities.
     * Functions such as malloc(), calloc(), and realloc() return a void*, allowing memory allocation
       for any data type.

     int* arr = (int*) malloc(5 * sizeof(int));

     * Void pointers enable functions to work with multiple data types. For example, the comparison
       function used by qsort() accepts void pointers.
     * Many dynamic data structures such as linked lists, stacks, queues, and trees use void pointers to
       store elements of different types.
     * Void pointers are commonly used for explicit typecasting between different pointer types.
     * Many library functions use void pointers to provide flexible interfaces that work with arbitrary
       data.

Advantages of Void Pointers
   Void pointers provide flexibility by allowing a single pointer type to work with multiple data types
   and generic programming constructs.
     * Can store the address of variables of any data type.
     * Useful for implementing generic functions and libraries.
     * Widely used in dynamic memory allocation functions such as malloc() and calloc().
     * Helps in implementing generic data structures like linked lists, trees, and queues.

Limitations of Void Pointers
   Despite their flexibility, void pointers reduce type safety and require careful handling.
     * Cannot be dereferenced directly without typecasting.
     * Pointer arithmetic on void pointers is not allowed by the C standard.
     * Incorrect typecasting can lead to undefined behavior.
     * Provides less compile-time type checking compared to typed pointers.

   A void pointer is used in C as a kind of generic pointer. A void pointer variable can be used to
   contain the address of any variable type. The problem with a void pointer is once you have assigned
   an address to the pointer, the information about the type of variable is no longer available for the
   compiler to check against.

   In general, void pointers should be avoided since the type of the variable whose address is in the
   void pointer is no longer available to the compiler. On the other hand, there are cases where a void
   pointer is very handy. However it is up to the programmer to know the type of variable whose address
   is in the void pointer variable and to use it properly.

   Much of older C source has C style casts between type pointers and void pointers. This is not
   necessary with modern compilers and should be avoided.

   The size of a void pointer variable is known. What is not known is the size of the variable whose
   pointer is in the void pointer variable. For instance here are some source examples.

Benefits:
    void * and char * (or qualified variants thereof) are the only types that allow you somewhat
    direct access to the machine representation of values in memory without inducing undefined
    behavior. Restrictions still apply, of course, and they don)t necessarily allow you to convert
    freely between pointer types without breaking aliasing rules.

    void * makes defining a good NULL muchmuch easier. With it, NULL can be defined as a singular constant
    that has a single pointer type, usually ((void *)0) with minimal compiler-specific trickery.

    For comparison, in C++-pre11, because void * doesn)t freely coerce to any other type, NULL had
    to either be defined as just 0 or some special token like __null that maybe allowed the compiler to
    warn about misuse, but which otherwise behaved just like literal 0. Literal 0 is a really bad NULL,
    because it)s just an int unless the compiler has special knowledge otherwise, and in situations
    like ... arguments or template jiggering the compiler has no such knowledge. Post-C++11, NULL can
    be defined as nullptr, which establishes const volatile void * and decltype(nullptr) as the top and
    bottom of the pointer type lattice, respectively-i.e., any pointer type coerces freely/safely to
    const volatile void * and decltype(nullptr) coerces freely/safely to any pointer type, but not vice
    versa. In C the top is const volatile void * and the bottom is void *, which means its "lattice"
    is really just a weird almost-loop.

    You won)t need to implement things like memset, malloc, or free for every possible argument/return
    type, on the off chance the compiler has different calling conventions for void * and other pointer
    types. One size fits all.

    void * is excellent for use with callbacks (e.g., pthread_create) where you need for the client code
    to be able to pass through in some arbitrary context, or for cleanup/destructors where you don)t
    care what)s in the referent memory as long as things that need cleaned up get cleaned up. I tend
    to prefer a scheme like

    if my code doesn)t need to impose any requirements on the pointed-to type, and this lets the client
    pass through anything with any cast hidden inside the something implementation.

    When GNU-style &&label expressions are used, they hand back a void *. You have no more type
    information than that, so you)re only allowed to use (possibly qualified) void *s with computed
    goto. I generally prefer const void * for computed goto, since there)s roughly zero chance I)ll
    want something to write through that pointer.

    You certainly wouldn)t/shouldn)t use void * if you have any concrete knowledge of its referent type;
    if you know it points to a long, use long * so you can dereference the thing without a cast. Otherwise
    you)re just kneecapping the type system for no good reason.

    void * is typically used to refer to a raw memory buffer xor NULL, but that)s as self-documenting
    as it gets; beyond that, no telling what it might refer to.

    void * makes it very easy to mask undefined behavior when type-punning.

    void * may make it harder than necessary for the compiler to reason about aliasing, although C99
    restrict/equivalent can help with that.

    Pointers of any type can have weird interaction with literal 0s, which usually coerce to null
    pointers in the right contexts. For example, in a ... argument list or (in C only) an unspecified
    () argument list, literal 0 will be passed as int, not autoconverted somehow to NULL. You)ll need
    to either use NULL or explicitly cast 0 to the proper type.

    pointer/integer types may use other formats when being passed as arguments and under the varargs scheme
    the compiler doesn)t know to cast things for you. Portable code must therefore cast non-void *s to
    void * (with/without const/volatile) before passing them to %p, which is one of the very few common
    cases where you)ll need to explicitly cast to void *. Non-varargs arguments (i.e., not under the

    If you)re writing generic code (e.g., via macros), void * is a weird corner case. You can)t

If a function accepts a pointer-to-void type, it will accept any kind of pointer without complaint. This
will make it possible for the function to accept pointers to a variety of similar types of structures
without ugly casts in the client code, but will prevent the compiler from notifying a programmer that
anything is wrong if e.g. the programmer accidentally passes the address of a pointer to such a structure,
rather than passing the address of such a structure, or vice versa. For example, it may be useful to
have a function that can work with a variety of structure types having the following general form:

struct {
	uint32_t count;
	uint16_t flags;
	someType data[];
} countedSomeTypeArray;

so as to allow use with objects of static or automatic duration. Having such a function accept a pointer
to any particular type would make it necessary for client code to cast the address of any type passed
to such a function. Having the function accept void* would avoid that requirement.

On the other hand, in cases like this, another approach can sometimes be useful: wrap the function call
in a macro which effectively tests that the argument is likely to be a pointer of proper type.

#define showThing(x) (doShowThing(sizeof (x)->count : (countedTypeArray)(x) : 0))

While it would be possible to invoke this macro with a pointer to some structure type that)s unrelated
to the above but happens to contain a member called n, this approach would ensure that e.g. accidentally
passing a pointer to an array of such items would yield a compilation error.

Note that this technique is only suitable for use on compiler configurations that aren)t specialized
exclusively for purposes that would not benefit from C)s historic ability to process a variety of similar
structures using the same code via the Common Initial Sequence guarantee. The -fstrict-aliasing modes
of gcc and clang, for example, are specialized in such a fashion, though the -fstrict-aliasing mode of
icc isn)t, and would thus be suitable for use with the above construct.

A void pointer in C (void *) is a generic pointer type that can hold the address of any data object
without specifying that object´s type. It is the language´s untyped pointer, used where type-specific
semantics are unnecessary or must be deferred.

Definition and properties
Syntax: void *p;
p can store the address of any object type (int, double, struct, array, etc.).	No dereference type: you
cannot directly dereference ( *p ) or perform pointer arithmetic on a void * because the pointed-to object
size is unknown.  Implicit conversion: assignment from any object pointer type to void * is implicit in C;
conversion back to the original object pointer type requires an explicit cast in C++ and is implicit in C but
often written explicitly for clarity.  Alignment: a void * must follow the platform´s pointer alignment
rules;
it can point only to properly aligned objects.

Advantages
Generic data containers and APIs: allows writing functions and data structures (e.g., qsort, bsearch,
generic linked lists, containers) that accept or store pointers to arbitrary types.  Abstraction:
separates interface from implementation details; callers can provide pointers to their own types without
exposing internals.  Interfacing with raw memory: useful for memory allocators (malloc returns void *),
byte buffers, and low-level I/O where data type is determined at runtime.  Polymorphism-like behavior in
C: enables heterogeneous collections and callbacks carrying arbitrary user data (void *user_data).

Disadvantages and pitfalls
Loss of type safety: compiler cannot check that you convert back to the correct pointer type, increasing
risk of undefined behavior from incorrect casts.  Manual bookkeeping: code must track the pointed-to
type/size, increasing cognitive and maintenance burden.  No direct dereference or arithmetic: must cast to
a concrete pointer type to access data, which can lead to incorrect pointer arithmetic if size is
mistaken.  Potential alignment and strict-aliasing issues: incorrect casts or treating memory as the wrong
type can violate strict-aliasing rules and cause subtle bugs or misoptimizations.  Readability and
maintainability: heavy use of void * obscures data flow and intent compared with typed pointers or
structs/unions.

When to use void * (practical guidance)
Implementing generic libraries: when a function or data structure legitimately needs to accept or store
pointers to many possible types (e.g., qsort comparator with void * elements, container APIs).	Wrapping
raw memory: when writing allocators, memory-manipulation utilities, serialization/deserialization, or APIs
that pass opaque handles.  Callback/user-data patterns: when an API needs to accept user-provided context
pointers without knowing their types.  Interfacing with C APIs that require or return void * (e.g.,
malloc, thread entry functions).

When not to use void *
When a concrete type is known: prefer typed pointers; they provide compile-time checks and clearer intent.
When type safety matters: avoid void * in public interfaces where misuse is likely; use structs, unions,
or polymorphic design patterns instead.  For simple code clarity: if only one type is ever used, a typed
pointer is superior.

Practical rules of thumb
Limit scope: confine void * use to internal or well-documented boundaries; prefer typed wrappers at public
interfaces.  Document type contract: when a function accepts void *, clearly document expected type and
ownership (who frees memory).  Cast immediately and locally: cast the void * to the concrete type in a
narrow scope where you know the type, minimizing propagation of untyped pointers.  Check sizes and
alignment: when working with raw buffers, carry explicit size parameters and consider memcpy for copying
to avoid aliasing issues.  Prefer safer alternatives: use unions, tagged structs (type field + union), or
container-specific typed implementations when possible.

Examples (concise)
malloc returns void * so the caller can cast to the needed pointer type.  qsort elements are passed as
const void * to a comparator; comparator casts back to element type to compare.  Thread start functions
often accept void *arg so callers can pass arbitrary context.

Summary Use void * when genuine run-time polymorphism, raw-memory handling, or opaque handles are required,
and confine its use behind clear contracts and casts. Prefer typed pointers and structured alternatives where
compile-time safety and clarity matter.

What is void?

In C and C++, void is a keyword used to indicate the absence of any type. It is typically used in three
primary contexts:

Void Functions:
    When a function is declared as void, it means that the function does not return a value. This is
    useful when the function´s purpose is solely to perform an action, such as printing to the console
    or modifying a global variable.

Example:

void printHello() {
	printf("Hello, World!\n");
}

Here, printHello() performs an action but does not return any value.

Void Pointers:
    A void pointer (void *) is a special type of pointer that can point to any data type. However,
    since the type is not specified, you must cast it to the appropriate type before dereferencing it.

Example:

void *ptr;
int a = 10;
ptr = &a;  // ptr now points to an integer

Here, ptr is a void pointer that can later be cast to an int * to access the integer value.

Void in Function Parameters:
    When used as a parameter, void specifies that the function does not accept any arguments. This is
    common in C to explicitly indicate that a function should not take any parameters.

Example:

void doNothing(void) {
	// This function does nothing and takes no arguments
}

The sizeof Operator
The sizeof operator is used to determine the size, in bytes, of a data type or variable in C and C++. It
is evaluated at compile time and returns the size of the specified type or object.

Example:

int x = 10;
printf("Size of int: %zu bytes\n", sizeof(int));  // Typically prints 4 bytes on most systems
printf("Size of x: %zu bytes\n", sizeof(x));      // Also prints 4 bytes

What About sizeof(void)?
The question of sizeof(void) is where things can get tricky. The sizeof operator is designed to return
the size of a specific data type, but void is not a data type with a defined size-it´s an absence of type.

Because void represents "no type" or "no value," it does not make sense to ask for the size of void. As
a result:
    sizeof(void): This is not valid in C or C++ and will result in a compilation error. The language
    standard does not define the size of void because there is nothing to size-it´s an absence of data.

However, things change a bit when it comes to pointers:
    sizeof(void *): This is perfectly valid and returns the size of a pointer, regardless of the data
    type it points to. In most systems, the size of a pointer is typically 4 bytes on a 32-bit system
    and 8 bytes on a 64-bit system.

printf("Size of void pointer: %zu bytes\n", sizeof(void *));  // Typically prints 8 bytes on a 64-bit system

This is because the pointer itself has a fixed size, determined by the architecture of the machine,
regardless of what type it points to - or even if it points to void.

Why Is There No sizeof(void)?
The absence of a defined sizeof(void) is by design. Since void doesn´t represent any specific data,
asking for its size is like asking for the size of "nothing." The language designers ensured that this
would be a compile-time error to avoid confusion.

If you ever find yourself needing to use sizeof(void) for some reason, you are likely approaching the
problem from the wrong angle. Instead, consider what you actually need: Is it the size of a pointer? Or
are you dealing with a data type that needs to be specified?

Practical Implications in Programming
Understanding that void is a placeholder for "no type" is crucial for using it correctly. Here´s how
this knowledge applies to your coding practice:
    - Void Functions: Use void to define functions that do not return a value. This is common in procedures
      that modify global state or perform I/O operations.
    - Void Pointers: Use void * when you need a generic pointer. This is common in functions that need
      to handle different types of data without knowing the type in advance, such as memory management
      functions like malloc.
    - Avoiding Errors: If you mistakenly try to use sizeof(void), refocus on what you actually need to
      size. Remember that sizeof(void *) is valid and gives you the size of a pointer, which can be useful
      in certain contexts.

Conclusion
The void type and the sizeof operator are foundational in C and C++, but they serve very different
purposes. Understanding why sizeof(void) is not valid and how to use void correctly will help you write
more accurate and effective code. By knowing when and how to use void, you can take full advantage of
its flexibility while avoiding common pitfalls.

Remember, in programming, clarity and precision are key. Understanding the tools at your disposal,
such as void and sizeof, will make you a more proficient programmer, capable of tackling a wide range
of problems with confidence.
