google query: i3 with SXHKD

Using sxhkd (Simple X Hotkey Daemon) with the i3 window manager lets you move your keybindings out of the main
i3 configuration file and into a clean, dedicated hotkey daemon.

How to Set It Up
  * Install sxhkd: Use your package manager, such as sudo pacman -S sxhkd on Arch Linux.
  * Create the config file: Make a directory at ~/.config/sxhkd and create an sxhkdrc file inside it.
  * Add autostart to i3: Put 'exec_always --no-startup-id sxhkd' in your ~/.config/i3/config file so it
    launches with the window manager.
  * Keep core bindings in i3: Leave essential window manager rules (like defining $mod or specific focus/mode
    hooks) inside your i3 config if needed, but route actions through i3-msg.

Example Configuration (sxhkdrc)
To control i3 using sxhkd, pair your key combinations with the i3-msg utility:

[conf]
# Launch a terminal (Alacritty, Kitty, etc.)
super + Return
  alacritty

# Focus or switch workspaces 1-9
super + {1-9}
  i3-msg workspace number {1-9}

# Move focused container to workspace 1-9
super + shift + {1-9}
  i3-msg move container to workspace number {1-9}

# Kill focused window
super + shift + c
  i3-msg kill

# Restart i3 in place
super + shift + r
  i3-msg restart

Pros and Cons
  * Cleaner i3 Config: Shrinks your main i3 config file by moving hundreds of lines of keymaps into a
    dedicated syntax.
  * Better Syntax: sxhkd supports powerful nested braces and chord chains (e.g., super + o ; {e,w} ...).
  * Window Manager Independent: If you switch to another X11 window manager later (like Openbox or DWM), your
    hotkey configuration remains exactly the same.
  * Complex Modes Struggle: sxhkd can feel limited compared to i3´s native mode system if you rely on complex,
    multi-layered stateful keybinding graphs that do not automatically terminate on a single action.

You can use sxhkd (Simple X Hotkey Daemon) alongside the i3 window manager to standardize your hotkeys across
different desktop environments or keep your i3 configuration file clean.

Setting Up sxhkd with i3
To make sxhkd work with i3, you need to install the daemon, launch it automatically through your i3 config,
and map your shortcuts using i3-msg.

  * Install sxhkd using your package manager (for example, sudo pacman -S sxhkd on Arch Linux or sudo apt
    install sxhkd on Debian/Ubuntu).
  * Create a config directory at ~/.config/sxhkd/ and make a file named sxhkdrc inside it.
  * Add sxhkd to your i3 configuration file (~/.config/i3/config) so it starts automatically when i3 launches:
    exec_always --no-startup-id sxhkd

Writing the Configuration
Inside your ~/.config/sxhkd/sxhkdrc file, define your keybindings by putting the key combination on the first
line, a Tab character next, and the shell command to run. For controlling i3 actions, use the i3-msg utility.

Example keybindings for sxhkdrc:

# Launch a terminal
super + Return
    alacritty

# Change workspace focus
super + {1-9,0}
    i3-msg workspace number {1-9,10}

# Move container to workspace
super + shift + {1-9,0}
    i3-msg move container to workspace number {1-9,10}

# Kill focused window
super + shift + c
    i3-msg kill

Sxhkd: Configuring Window Manager Independent Keybindings

You can run sxhkd (Simple X Hotkey Daemon) with the i3 window manager by starting it inside your i3
configuration file and mapping your shortcuts using i3-msg.

Setting Up SXHKD for i3
1. Add SXHKD to your i3 Configuration
Open your i3 config file (usually located at ~/.config/i3/config) and add this line at the end to start sxhkd
automatically when i3 launches:
exec --no-startup-id sxhkd

2. Create the SXHKD Configuration File
Create a configuration directory and file at ~/.config/sxhkd/sxhkdrc:
mkdir -p ~/.config/sxhkd
touch ~/.config/sxhkd/sxhkdrc

3. Write Keybindings Using i3-msg
In your sxhkdrc, define key combinations followed by a tab and the command you want to run. Control i3 actions
by calling i3-msg:

# Focus specific workspace
super + {1-9,0}
    i3-msg workspace number {1-9,10}

# Move focused container to workspace
super + shift + {1-9,0}
    i3-msg move container to workspace number {1-9,10}

# Kill focused window
super + shift + q
    i3-msg kill

# Restart i3 in place
super + shift + r
    i3-msg restart

sxhkd: why another keybinders?
February 18, 2024

System
The concept of keybinders should not be a secret for you. If you´re using a tiling windows manager, you are
even probably already familiar with assigning keyboard shortcuts to actions within its configuration file.
That´s what I used to do for years using awesomewm, i3, or dwm. Once I moved to bspwm, I´ve also be introduced
to [11]sxhkd and I first missed the point of yet another keybinders.  Let´s see why sxhkd stands out among the
various keybinders available for Linux.

In simple words, sxhkd´s secret is the format of its configuration file which supports a simple notation for
mapping multiple shortcuts to multiple commands in parallel. This allows for a streamlined configuration file
where you "group" similar keybindings instead of duplicated them.  Here are some examples of what that means:

# Assign 3 keybindings to 3 commands in just 2 lines:
# alt + g   > launch gvim
# alt + f   > launch firefox
# alt + t   > launch thunderbird

mod1 + {g,f,t}
        {gvim,firefox,thunderbird}

# Assign 3 keybindings to 3 commands (changing the argument of a command) in just 2 lines:
# super + alt + XF86Eject           > run sudo systemctl suspend
# super + ctrl + XF86Eject          > run sudo systemctl reboot
# super + alt + ctrl + XF86Eject    > run sudo systemctl poweroff

super + {alt,ctrl,alt + ctrl} + XF86Eject
        sudo systemctl {suspend,reboot,poweroff}

This is what you may be used too. Just in a more compressed format. Ready for more craziness?

# Assign 18 keybindings to 18 commands in just 2 lines again:
# control + [1-9]           > switch to desktop [1-9] in bspwm
# control + shift + [1-9]   > move window to desktop [1-9] in bspwm

control+{_,shift+}{1-9}
    bspc {desktop -f,node -d} '^{1-9}' --follow

BTW, this also applies to remapping your mouse buttons like so:

button12
    xdotool key control+Tab

Very useful when you have programmable buttons like on [12]this little guy.

By now, I know that it´s hard to please my avid readers. Good news, sxhkd can also bind a command to a single
press of a key. This is done by binding to a chord chain composed of the key press and key release event of a
single key, as in the following:

# Press the super key to launch rofi in drun mode
Super_L; @Super_L
    rofi -show drun

So I´ll leave it here and hope you´ll give this tiny, though extremely powerful, tool a try.

Use sxhkd along with i3

If you wanted to use a different hotkey daemon with i3, you can use sxhkd.
I have been using it for a week and I didn´t feel any slowdowns.

Advantages of using sxhkd:
 * Make your setup more modular. Make your i3 config smaller
 * It´s DE/WM agnostic
 * Much better parser compared to i3's. For example, changing workspace

bindsym $mod + F5 workspace 5
bindsym $mod + F6 workspace 6
bindsym $mod + F7 workspace 7
bindsym $mod + F8 workspace 8

can be replaced by:

alt + F{1-4}
    i3-msg workspace {5-8}

How to shift from i3 hotkey manager to sxhkd
There are only a few things to keep in mind

  * If you move all your keybinds from i3, your config file won´t work. Your i3 config file must contain
    this two lines at minimum. Otherwise, your i3 will crash.
# i3 config file (v3)

  * All your i3 keybinds in sxhkd must start with i3-msg. Example, using workspace focus movement:
alt + {Left,Down,Up,Right}
    i3-msg focus {left,down,up,right}

That´s all. Check out the [https://github.com/baskerville/sxhkd/]sxhkd github page for more examples. You can
setup very complex keybinds using it.

Installing i3-gaps in Arch
2021-04-25

   Hi again. I recently came across this guide for installing i3-gaps in Arch (or any Arch-related
   distro, such as Manjaro or Arch Labs), and thought I´d share it on here.

   Before actually installing anything you should (obviously) update the database and the system:
$> sudo pacman -Syyu

   (N.B. This took a 1.2 GB download on my system.)

   Install i3 gaps:
$> sudo pacman -S i3-gaps

   Lastly, install fonts and the status bar:
$> sudo pacman -S ttf-dejavu i3status

   You will need ttf-dejavu for i3 so that text will display correctly. You will need i3status so that
   the status bar will work and not show an error message.

   NOTE - i3-gaps and i3-wm are different packages. The first is a fork of the second. Install the first
   one if you want gaps.

   https://low-orbit.net/arch-linux-how-to-install-i3-gaps
